# Project review — 2026-10-01

Reviewed baseline: `8b5d000` (`refactor: modernize and harden Go 1.27 support`).
This is a dated review, not a second roadmap or an agent instruction file.

The architecture has useful boundaries: a dependency-free deterministic kernel,
a pure reference protocol, explicit durability barriers, a separate checker,
versioned artifacts, and an isolated production-core adapter. Existing tests and
published evidence verification passed. No protocol defect was confirmed in
this review; passing bounded tests does not establish protocol safety.

## Prioritized improvements

### 1. Produce failure-preservation evidence before expanding capabilities

**Priority: high; research gap, not an implementation regression.**
[The research protocol](../../RESEARCH_PROTOCOL.md) defines the primary claim,
but [the production projector](../../semanticplan/projector.go) identifies
network choices by endpoints/incarnations/send occurrences.
[The synthetic study](../../internal/projectionstudy/study.go) already shows
that complete occurrence coverage can move a fault to another logical operation.
The causal prototype is confined to that toy study.

Next, pin one reviewed vulnerable/fixed defect pair, a failure predicate, and
its capability boundary. Add operation/dependency identity and explicit retry
and batch semantics to a versioned production mapping. Reject conflicting
batch mappings before execution. Compare seed-only, interval, and semantic
replay under matched budgets, then compare reductions with the same predicate.
Publish exclusions and operational failures alongside successful runs. Use
[RESEARCH_PROTOCOL.md](../../RESEARCH_PROTOCOL.md) as the acceptance contract;
adding more adapters or scenarios alone does not close this evidence gap.

### 2. Strengthen the canonical-cache correctness gate

**Priority: high for future cache changes; validation gap.**
[The cache](../../explore/explore.go) checks exact canonical bytes after hashing
and includes remaining search depth in its identity. Those are good safeguards.
[CANONICAL_STATE.md](../../CANONICAL_STATE.md#validation-gate) explicitly leaves
a broader false-merge and fully enumerated matrix outstanding. Existing model,
collision, sensitivity, and smoke tests provide a useful starting point.

Add small fully enumerable reference scenarios spanning pending persistence,
timer generations, crash incarnations, message order, snapshots, and membership.
Compare reachable terminal outcomes and fingerprints with cache off/on; test
deliberately incomplete encoders against divergent futures. Separate exhaustive
checks from resource-truncated searches. Profile encoding allocations and cache
memory only after this gate; the published null-hit study does not demonstrate
pruning benefit.

### 3. Extend decoder fuzzing

**Priority: medium; robustness opportunity.**
The existing fuzz entry points cover binary KV command/checkpoint decoding in
[apporacle tests](../../apporacle/apporacle_test.go). The JSON boundaries in
`artifact`, `trace`, `semanticplan`, `evaluation`, and `mutant` have focused
tests and size/strictness checks but no fuzz entry points.

Seed fuzzers with small valid documents, escaped duplicate names, nested
objects, unknown fields, trailing values, boundary integers, and malformed
lengths. Assert no panics, stable rejection, and valid decode/encode/decode
behavior using each format's actual normalization contract. Avoid feeding
multi-megabyte published tapes into every seed run. Add bounded fuzz jobs after
the targets are useful; keep routine checks predictable.

### 4. Review shared publication mechanics without flattening their contracts

**Priority: medium; maintenance opportunity.**
Atomic staging, sync, no-clobber linking, and directory sync are repeated in
[draft](../../cmd/draft/main.go), [draft-mutants](../../cmd/draft-mutants/main.go),
[draft-eval](../../cmd/draft-eval/main.go), and
[draft-etcd](../../adapters/etcdraft/cmd/draft-etcd/main.go).
Their post-commit cleanup/reporting behavior differs. Cross-adapter bundles
add manifest-last commit and recovery semantics.

Consider sharing a narrowly scoped single-file publication primitive while
keeping evaluation preflight and bundle transactions separate. Before changing
it, test link failure, an existing destination, directory-sync failure, and
cleanup failure after commit. Preserve the distinction between a failed write
and a committed result whose cleanup or durability confirmation failed. No
publication defect was established here, so this refactor can wait for a task
that needs to change these paths.

### 5. Make subcommand help exit successfully

**Priority: low; confirmed CLI behavior.**
A built `draft run --help` prints help and returns exit code `2` because
[flag parsing](../../cmd/draft/main.go) treats `flag.ErrHelp` like invalid input.
Top-level `draft help` returns `0`. This makes ordinary help look like an error
to shell wrappers. Handle `flag.ErrHelp` as success consistently across command
entry points, with small help/invalid-argument checks. This behavior was
observed and recorded; runtime code was not changed in this cleanup.

## Context and workflow cleanups implemented

- Added a compact root [AGENTS.md](../../AGENTS.md) with task-to-code/document
  routing, deterministic contracts, verification tiers, and guidance to read
  large evidence selectively. Added an [adapter guide](../../adapters/etcdraft/AGENTS.md)
  where its separate module and RawNode restrictions matter.
- Added [tools/check.sh](../../tools/check.sh): `quick` checks both modules;
  `evidence` verifies independent KV vectors, both studies, both cross-adapter
  cases, and their checksum manifests. CI now calls the same evidence command.
- Shortened the README's repeated status inventory and routed development
  checks through the script. CLI examples place generated files in the existing
  ignored `.research-bin/`, avoiding scratch files in source context/provenance.
- Centralized historical evaluation regeneration in
  [REPRODUCIBILITY.md](../../REPRODUCIBILITY.md#regenerating-the-bounded-evaluation),
  pinned its historical toolchain explicitly, and used a separate worktree.
  The evaluation document links to that recipe instead of duplicating it.
- Preserved detailed schema/research documents and historical artifact bytes.

Keep the root guide small. Put behavior in its owning contract, live priorities
in the research protocol/issues, and dated observations in reviews such as this
one. Avoid creating another always-loaded summary of all project documents.

## Validation and limits

Passed root and nested adapter tests/vet, formatting, module verification, and
`go mod tidy -diff` with a writable temporary build cache. Passed the independent
Python KV self-test, deterministic projection regeneration, published evaluation
verification, source-bound verification of both cross-adapter cases, and all
four checksum manifests. Exercised script argument rejection and ran the
evidence script from outside the repository to verify path handling.

This review sampled implementations and contracts; it was not a line-by-line
Raft proof, an upstream audit, or a new effectiveness study. Race detection,
the minimum-Go matrix, long fuzz campaigns, and historical evaluation/mutant
regeneration were not rerun. CI retains its existing race, minimum-toolchain,
and repeated-determinism checks.
